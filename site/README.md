# site/

Rune's single-page website, served at **rune.banast.as**. It's static: one `index.html` with inline CSS and JS, `legal.html`, `404.html` (Pages serves it, with a 404, for any path the site doesn't have; without it every missing path, `appcast.xml` before the first release among them, got `index.html` with a 200), the pixel favicon, and the two HUD fonts. There's no build step and nothing loads from other servers. It started as a copy of Blit's `site/` (`../blit/site/`, 2026-10-07) and is Rune's own from there (PRD §7: no code shared between the apps).

- **Design:** the HUD's rules, as on Blit's site (PRD §0, V1-V14). The palette is black and grey (`HUDColor`), with muted red `#b35c5c` only for failures and conflicts (its tint `#c98080` for failure text). Type is Silkscreen for labels and VT323 for terminal text; native chrome in the simulated window uses the system font, and editor text a system monospaced font, never VT323 (A15). Pixel glyphs, the app icon, the menu bar's ᚱ and its marching line are drawn from the same 1-bit grids the app uses (`PixelGlyphs.swift`, §5.11, `NibMark.rune`). The only other colors are An Old Hope · Rune's, inside editor-area samples (the simulated window, the conflict block, the `script.js` excerpt), as A1 and A4 keep the scheme's colors to the text. Everything animated respects Reduce Motion: the tagline's `_` stays lit, the simulation shows where it ends, nothing marches, the HUD shows without its CRT switch-on.
- **The simulation:** a scratch.md with a generated packing list (no real files or names), typed into, saved, uploaded, receipted by the other Mac, then merged with that Mac's version while this one has unsent typing. Every strip, HUD and log line is in the words Rune's code uses (`SyncState.line`, `SyncHUD`, `SyncLogDisplay`, `Document`), this Mac called Studio and the other Air, with the time between events shortened. The HUD starts closed; the status line opens and closes it, as in the app. The SHA-256 in the FILE panel is the demo text's own (SubtleCrypto; "—" outside a secure context).
- **Copy:** short on purpose (the pass of 2026-10-07): four cards a section, a sentence or two each, no state-by-state legend, no test counts. Detail belongs in the spec sheet or nowhere; add a card only by taking one out.
- **Numbers:** every number comes from the PRD: the guarantees and timings from §4.1 and §4.3, the measured rows from §6.5's table (the Mac mini), save-to-other-Mac latency from M0's S1b (§8, M0 results; §4.10), fidelity (99.97% of the reference files' characters) from §8's HL8 second tier, the 33 languages from §8's "CSV and logs", the price, activations and trial from DS4 and §10 question 13. The `script.js` excerpt is a generated reference file (`fidelity/reference/`) in the colors Sublime Text dumped for it (`fidelity/sublime/script.js.json`). Change a number here when the PRD's changes.
- **Selling:** $19 one-time through Lemon Squeezy, a license for 3 Macs, a 7-day trial on each Mac (read-only after it, never stopping saving, sync, History or the journal: DS4), 30-day refunds. Download and Buy are inactive while `LIVE = false` in index.html ("Coming soon", "Checkout opens soon"). The Buy button's `data-checkout` is Rune's Lemon Squeezy product (2026-10-08: store 484060, `banastas.lemonsqueezy.com`, Blit's and Rune's; product 1423364, in test mode), with `?embed=1&desc=0` as Blit's; `?checkout=test` turns the button on to try the checkout before launch. To go live:
  1. If the product was made in test mode, copy it to live mode and put the live checkout link here and in the app (`LicenseConfig.buyURL`, with its product ID in `LicenseConfig.productID`).
  2. Set `LIVE = true` in index.html (turns on Download and Buy), and `LicenseConfig.enforced = true` in the app; publish that release.
- **Legal:** `legal.html` has the license terms, privacy policy and refund policy, from Blit's. The privacy policy says what Rune actually sends: your files go only through Apple's iCloud Drive (with small notes in a hidden `.nib` folder beside them: Mac names, file names, SHA-256 hashes, sizes and times, never the text); an update check to `https://rune.banast.as/appcast.xml` once a day (Sparkle, off in Settings › General); license checks to api.lemonsqueezy.com once licensing ships; no analytics or telemetry. Seller: banast.as; contact: me@banast.as. Dated 2026-10-07; update the date when it changes.
- **Fonts:** Silkscreen and VT323 are under the SIL Open Font License; the license texts are in `fonts/`.

Preview locally:

```bash
python3 -m http.server 8765 --directory site
```

Hosting: Cloudflare Pages, project `rune` (`rune-52e.pages.dev`), with this repository (banastas/Rune) as the source, production branch `main`, no build command and `site` as the output directory; `rune.banast.as` is its custom domain. A retry in Pages rebuilds that deployment's own commit, not the branch's newest: to deploy the newest, push or Create deployment. `brand/` has the link preview (`rune-card-1200x630.png`, the `og:image`), Lemon Squeezy's product image (`rune-product-1600x1200.png`), the GitHub repository's social preview (`rune-github-1280x640.png`, Settings › General › Social preview) and the store's logo, the family mark (`banastas-logo-*.png`, `scripts/brand/family-mark.swift`); the first three drawn from `scripts/brand/rune-brand.html` by `scripts/make-brand.sh` (WebKit, offscreen): run it after changing that page.

## Downloads and updates

`PUBLISH=1 INSTALL=1 NOTES="…" scripts/release.sh` puts the notarized build here: `downloads/Rune-<version>-<build>.zip` (the one Sparkle updates point to, a name of its own for each build) and `downloads/Rune.zip` (the Download buttons), and writes `appcast.xml`, the update feed the app checks once a day (`SUFeedURL` in `Support/Info.plist`); then it commits those and pushes, and Cloudflare Pages deploys them. Each release is signed with the Sparkle EdDSA key in the release Mac's Keychain (Blit's key); the public key is in `Support/Info.plist`. Only the current release is kept here.
