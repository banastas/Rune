# site/

Rune's single-page website, served at **rune.banast.as**. It's static: one `index.html` with inline CSS and JS, `legal.html`, the pixel favicon, and the two HUD fonts. There's no build step and nothing loads from other servers. It started as a copy of Blit's `site/` (`../blit/site/`, 2026-10-07) and is Rune's own from there (PRD §7: no code shared between the apps).

- **Design:** the HUD's rules, as on Blit's site (PRD §0, V1-V14). The palette is black and grey (`HUDColor`), with muted red `#b35c5c` only for failures and conflicts (its tint `#c98080` for failure text). Type is Silkscreen for labels and VT323 for terminal text; native chrome in the simulated window uses the system font, and editor text a system monospaced font, never VT323 (A15). Pixel glyphs, the app icon, the menu bar's ᚱ and its marching line are drawn from the same 1-bit grids the app uses (`PixelGlyphs.swift`, §5.11, `NibMark.rune`). The only other colors are An Old Hope · Rune's, inside editor-area samples (the simulated window, the conflict block, the `script.js` excerpt), as A1 and A4 keep the scheme's colors to the text. Everything animated respects Reduce Motion: the tagline's `_` stays lit, the simulation shows where it ends, nothing marches, the HUD shows without its CRT switch-on.
- **The simulation:** a scratch.md with a generated packing list (no real files or names), typed into, saved, uploaded, receipted by the other Mac, then merged with that Mac's version while this one has unsent typing. Every strip, HUD and log line is in the words Rune's code uses (`SyncState.line`, `SyncHUD`, `SyncLogDisplay`, `Document`), this Mac called Studio and the other Air, with the time between events shortened. The strip's sync state opens and closes the HUD, as in the app. The SHA-256 in the FILE panel is the demo text's own (SubtleCrypto; "—" outside a secure context).
- **Numbers:** every number comes from the PRD: the guarantees and timings from §4.1 and §4.3, the performance table from §6.5 (measured on the Mac mini), save-to-other-Mac latency from M0's S1b (§8, M0 results; §4.10), fidelity (99.97%, 28,758 of 28,766 characters on 30 reference files) from §8's HL8 second tier, the 33 languages from §8's "CSV and logs", the test counts from §8's "Rune" entry (2026-10-07), the price, activations and trial from DS4 and §10 question 13. The `script.js` excerpt is a generated reference file (`fidelity/reference/`) in the colors Sublime Text dumped for it (`fidelity/sublime/script.js.json`). Change a number here when the PRD's changes.
- **Selling:** $19 one-time through Lemon Squeezy, a license for 3 Macs, a 7-day trial on each Mac (read-only after it, never stopping saving, sync, History or the journal: DS4), 30-day refunds. Download and Buy are inactive while `LIVE = false` in index.html ("Coming soon", "Checkout opens soon"). **Placeholder:** there's no Rune product in Lemon Squeezy yet, so the Buy button's `data-checkout` is empty, and `?checkout=test` does nothing until it has a link. To go live:
  1. Create the Rune product in Lemon Squeezy (3 activations a key) and put its checkout overlay link in the Buy button's `data-checkout` (keep `?embed=1&desc=0`, as Blit's). `?checkout=test` then turns the button on with a test-mode link.
  2. Publish a release so `downloads/Rune.zip` exists (below).
  3. Set `LIVE = true` in index.html (turns on Download and Buy), and give the app the same checkout link as its buy link once licensing (DS4) is built.
- **Legal:** `legal.html` has the license terms, privacy policy and refund policy, from Blit's. The privacy policy says what Rune actually sends: your files go only through Apple's iCloud Drive (with small notes in a hidden `.nib` folder beside them: Mac names, file names, SHA-256 hashes, sizes and times, never the text); an update check to `https://rune.banast.as/appcast.xml` once a day (Sparkle, off in Settings › General); license checks to api.lemonsqueezy.com once licensing ships; no analytics or telemetry. Seller: banast.as; contact: me@banast.as. Dated 2026-10-07; update the date when it changes.
- **Fonts:** Silkscreen and VT323 are under the SIL Open Font License; the license texts are in `fonts/`.

Hosting: Cloudflare Pages, with this repository (banastas/Rune) as the source, no build command and `site` as the output directory; then point `rune.banast.as` at the Pages project with a CNAME record. The link preview has no card image yet (Blit's has `brand/`); add one under `brand/` and an `og:image` when there is one.

## Downloads and updates

`PUBLISH=1 INSTALL=1 NOTES="…" scripts/release.sh` puts the notarized build here: `downloads/Rune-<version>-<build>.zip` (the one Sparkle updates point to, a name of its own for each build) and `downloads/Rune.zip` (the Download buttons), and writes `appcast.xml`, the update feed the app checks once a day (`SUFeedURL` in `Support/Info.plist`); then it commits those and pushes, and Cloudflare Pages deploys them. Each release is signed with the Sparkle EdDSA key in the release Mac's Keychain (Blit's key); the public key is in `Support/Info.plist`. Only the current release is kept here.
