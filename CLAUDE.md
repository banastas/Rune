## Rules that are settled (don't relitigate)

- **Safety rule (§8):** until M1 has passed (the user's call; its by-hand checks were skipped, not passed), Nib opens only test files (`iCloud Drive/Nib/Test/`, or `iCloud Drive/nib-spike/` in ad-hoc builds). Never read the contents of the user's real scratch files (`_scratch*.md` in iCloud Drive); spikes use generated text.
- **Sync (§4.3, §4.4, found the hard way, see M0/M1 results):** hold the file (pause sync) while open, the first hold **only once iCloud has finished uploading it** (a pause mid-upload crashes `fileproviderd` on macOS 27.0.1; `Document.waitForUpload`), while a re-hold after a fetch or refresh pauses at once (waiting, iCloud put the server's copy over Nib's); save **in place**, never by renaming a temp file (that drops the pause); upload now with fail-on-conflict; **never resume with `.preserveLocalChanges`**; a buffer may be replaced only when nothing is unsent (`Document.unsent`); iCloud's "current" and `fetchLatestRemoteVersion` can't be trusted for a held file, so the unpaused note (`Announcement`) plus a forced refresh (evict and download) decide; every iCloud call has a time limit (`CloudControl.within`).
- **Editor:** TextKit 2; nothing may touch `layoutManager` (it silently switches to TextKit 1).
- **Look and voice:** dark only (A17); Blit's HUD language for the strip (uppercase, middle dots, glyph and word, one muted red for problems); plain, literal copy (W1-W8).
- **No shared package with Blit (the user's call, 2026-09-29, PRD §7):** each app's code lives entirely in its own repository. Either may read the other's (`/Volumes/Photography/_GitHub/blit`) and copy or adapt what it needs; a copy's header names the repository, file and commit it came from, and from then on it's Nib's own code. Blit's pieces are in `nib/Vendor/FromBlit/`. Don't change Blit's repository from a Nib session unless asked.
- **Sold like Blit (the user's call, 2026-09-30, PRD question 13):** Sparkle from `nib.banast.as`, a single-page site in Blit's design, Lemon Squeezy licensing and third-party notices, all M3 work (DS2, DS3). The site waits for M3. $19, one-time, as Blit; a license activates 3 Macs. The trial (DS4): read-only after 7 days, never stopping saving, sync, History or the journal. Still open: clearing the name (question 14).
- **Name:** Nib, capitalized like Blit (decided 2026-09-28, replacing lowercase nib): the app, `Nib.app`, and its iCloud Drive folder. The bundle ID and container stay `com.banastas.nib` and `iCloud.com.banastas.nib`, as registered to the team; the Xcode target and scheme (`-scheme nib`), the source folder and `~/Library/Application Support/nib/` stay lowercase too.

```bash
cd NibKit && swift run nib-fidelity --report [scheme]   # the import report (HL4) for a scheme file, or for Sublime's own (read-only)
cd NibKit && swift build -c release --product nib-fidelity && cd .. && NibKit/.build/release/nib-fidelity --bench   # highlighting times at 2.4 and 5 MB (§6.5)
```

A Mac new to the team has to be registered as a device once, or team-signed builds stop at "Device … isn't registered in your developer account". That changes the user's developer account, so it's their step:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project nib.xcodeproj -scheme nib -configuration Debug -derivedDataPath build/DerivedData -destination "platform=macOS" -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
```

Don't name a NibKit product `nib`: Xcode makes a scheme for each package product, and one called `nib` took `-scheme nib` from the app (builds that compiled nothing of the app, 2026-09-29; the tool's product is `nib-cli`). `scripts/build-nib.sh` (which the scenario scripts use) checks the app is newer than every Swift source after building; after a build by hand, check the same (`find nib NibKit/Sources -name '*.swift' -newer build/DerivedData/Build/Products/Debug/Nib.app/Contents/MacOS/Nib.debug.dylib`). Scenario logs are in `build/scenarios/`; Nib's own Sync Log is `~/Library/Application Support/nib/sync.jsonl`, and a scenario's Nib's is `~/Library/Application Support/nib-scenarios/sync.jsonl` (its folder and settings are its own, PRD §6.4). While the user's Nib has the test file as its scratch (before `allowLiveScratch`), don't run the suite or the two-Mac test beside it: they start that file over. Build checks that mustn't touch the Debug app the user may be running go to their own `-derivedDataPath` (`build/DerivedData-check`), unregistered from LaunchServices after (`lsregister -u`).
