## Rules that are settled (don't relitigate)

- **Safety rule (§8):** lifted for the Nib in daily use on 2026-10-06 (the user's call; M1's by-hand checks were skipped, not passed). The test harness's Nib (`-NibScenario`) keeps it and opens only test files (`iCloud Drive/Rune/Test/` in Finder, `…/Mobile Documents/iCloud~com~banastas~nib/Documents/Test/` on disk, or `iCloud Drive/nib-spike/` in ad-hoc builds; `ScratchLocation.safetyRule`). Never read the contents of the user's real files: the scratch file `iCloud Drive/Rune/scratch.md`, `_scratch*.md` in iCloud Drive, or anything else they open in Rune; spikes and scenarios use generated text.
- **Sync (§4.3, §4.4, found the hard way, see M0/M1 results):** hold the file (pause sync) while open, the first hold **only once iCloud has finished uploading it** (a pause mid-upload crashes `fileproviderd` on macOS 27.0.1; `Document.waitForUpload`), while a re-hold after a fetch or refresh pauses at once (waiting, iCloud put the server's copy over Nib's); save **in place**, never by renaming a temp file (that drops the pause); upload now with fail-on-conflict; **never resume with `.preserveLocalChanges`**; a buffer may be replaced only when nothing is unsent (`Document.unsent`); iCloud's "current" and `fetchLatestRemoteVersion` can't be trusted for a held file, so the unpaused note (`Announcement`) plus a forced refresh (evict and download) decide; every iCloud call has a time limit (`CloudControl.within`).
- **Editor:** TextKit 2; nothing may touch `layoutManager` (it silently switches to TextKit 1). Colors are rendering attributes, never the text storage (§6.3); TextKit 2 draws each stretch of text into a layer of its own and redraws it only when its text changes, so new colors need `Editor.redrawText`, and a character typed in a colored run gets none of it until `Editor.paintEdited`. Never hand AppKit a range to scroll to (it crashed in `__NSTextViewScrollContainerViewToTextRange`): scroll by geometry, `nib/Views/Reveal.swift`. An Objective-C exception through Swift (a bad `NSString` range) crashes later, elsewhere.
- **The test harness (PRD §6.4):** a launch with `-NibScenario <name>` (`TestHarness.swift`, `#if DEBUG` only, so check Release compiles) is kept apart from the Rune in daily use: `Application Support/nib-scenarios/` and the defaults domain `com.banastas.nib.scenarios` (`NibPaths.isScenario`; every setting through `NibDefaults.store`), the safety rule, a bridge of its own, and no global shortcuts, menu bar extra, login item, Services, system recents, notifications or the Mac's Trash. To macOS it's still `com.banastas.nib`, so whatever macOS keeps by bundle ID has to be kept out by hand: window frames (`ScenarioWindows.keepFramesOut`), restored windows (`keepRestorationOut`, `FileWindow.unasked`), the login item (a stand-in in every Debug build). Its Nib keeps App Nap off, gives the Mac's focus back, and samples itself after 10 s without an answer (STALL lines). A launch-argument flag to compare old behavior with new is the habit (`-NibPaintEdits NO`, `-NibRestoreWindows YES`, `-NibAllowNap YES`); a flag's `NO` is a string, so read it with `bool(forKey:)`.
- **Running scenarios:** ask the user first and check `ps -axo command | grep -- -NibScenario` (other sessions share the scenario folders); say so before a suite on a Mac the user is at (keys typed meanwhile can land in test windows). One scenario: `build/DerivedData/Build/Products/Debug/Rune.app/Contents/MacOS/Rune -NibScenario <name> -NibScenarioLog "$PWD/build/scenarios/<name>.log" [args]`, after `scripts/build-nib.sh`. Don't edit `run-m1-scenarios.sh` while a suite runs (bash reads it as it goes). A variant gets its own log: `AS=merge-no-note run merge …`.
- **Disk writes (PRD §8, 2026-10-02):** a save writes only what differs from the file on disk; the journal logs each text's edits (one snapshot as it starts, lines written into room the log already has); a save that wrote much holds the next back (its bytes ÷ 80 KB/s, `SaveSchedule.rate`; the user's call); a check for another Mac's note set off by a change on disk reads the note as it is (a fresh read evicts it, and that looped for good). macOS counts a small write as a 16 KB page and metadata, 17-70 KB as Nib does them, so measure before adding writes per keystroke, pause or save: `scripts/run-writes.sh` (NibSync's `WriteMeter`). A disk-writes report counts a resource coalition, not a process: everything a Claude session starts (builds, tests, every scenario's Nib) counts as the Claude app's, and the process it names is only the one writing when the limit was crossed (a `TestHarness` frame in its stack means a scenario's Nib).
- **Look and voice:** dark only (A17); Blit's HUD language for the strip (uppercase, middle dots, glyph and word, one muted red for problems); plain, literal copy (W1-W8).
- **No shared package with Blit (the user's call, 2026-09-29, PRD §7):** each app's code lives entirely in its own repository. Either may read the other's (`/Volumes/Photography/_GitHub/blit`) and copy or adapt what it needs; a copy's header names the repository, file and commit it came from, and from then on it's Nib's own code. Blit's pieces are in `nib/Vendor/FromBlit/`. Don't change Blit's repository from a Nib session unless asked.
- **Sold like Blit (the user's call, 2026-09-30, PRD question 13):** Sparkle from `rune.banast.as` (Cloudflare Pages, from `main`), a single-page site in Blit's design (`site/`), Lemon Squeezy licensing and third-party notices (DS2, DS3). $19, one-time, as Blit; a license activates 3 Macs. The trial (DS4): read-only after 7 days, never stopping saving, sync, History or the journal.
- **Name:** **Rune** since 2026-10-07 (the user's call; PRD §8 "Rune", question 14; Nib from 2026-09-28, lowercase nib before): everything people see, the app `Rune.app`, its menus and words, the iCloud Drive folder's name, the `rune` command, the ᚱ art. Everything inside stays Nib: the bundle ID and container (`com.banastas.nib`, `iCloud.com.banastas.nib`, registered to the team), the code's names (NibKit, NibText, NibApp…), defaults keys and launch arguments (`-NibScenario`…), the hidden `.nib` folder, the Xcode target and scheme (`-scheme nib`), the source folder, the scripts' names and `~/Library/Application Support/nib/`. New user-visible text says Rune; don't rename the inside.
- **History is by path (PRD §8, 2026-10-03):** it thins a path only when that path opens again, so whatever ends a path's text there must carry its History (`FileCommands.carrySettings`, merging into the new path's through `History.move(to:)`, never into an open file's) or remove it (`ClosedItems.removeKept`); anything left stays for good. A scenario's untitled buffer closed with `Untitled.letGo` leaves nothing; a file a scenario makes still leaves its History, so remove it with the file (as `untitled` does its Save…'s).

## Build and check

Xcode 27. `xcode-select` may point at the Command Line Tools, so prefix builds with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (the scripts do).

```bash
scripts/run-m1-scenarios.sh                 # NibKit tests + every single-Mac scenario (about 15 minutes; test windows come and go)
SIGN=adhoc scripts/run-m1-scenarios.sh      # without the Apple account: no iCloud folder, tests in nib-spike/
scripts/run-m1-two-mac.sh a|b HH:MM         # the two-Mac test; same start time on both Macs
scripts/install-nib-cli.sh [folder]         # the `rune` command-line tool, into ~/.local/bin (AP4)
scripts/install-nib.sh                      # the Rune in daily use: a Release, as /Applications/Rune.app (quit it first; an old Nib.app goes to the Trash)
INSTALL=1 scripts/release.sh                # DS1: Developer ID, notarized and stapled, then /Applications/Rune.app (quit it first; the user's account: run by the user)
PUBLISH=1 INSTALL=1 VERSION=0.2 NOTES="…" scripts/release.sh   # DS2: …and an update: Sparkle-signed zip and appcast into site/, committed and pushed (the user's)
swift scripts/clean-test-leftovers.swift [--remove]   # old test runs' leftovers in the user's Nib folder and settings, to the Trash (a dry run without --remove)
scripts/acknowledgements.py [--check]       # About's third-party notices (DS3), from what Nib is built with
scripts/run-perf.sh                         # §6.5 measured: an optimized build with the scenarios, `perf`, ten cold launches
scripts/run-writes.sh [bytes]               # what Nib writes, by writer: open, typing, idle, another Mac's version, close (2.4 MB; 6-11 min; not beside the suite)
spike/run-s1b.sh a|b HH:MM [part2]          # M0 iCloud probes on two Macs
cd NibKit && swift test                     # the engine alone
swift scripts/make-icon.swift nib/AppIcon.icon   # the app icon (PRD §5.11), after changing its art
fidelity/run.sh                             # highlighting vs Sublime (HL7): Sublime dumps the reference files, then Nib compares
fidelity/run.sh compare                     # compare against the last dump only (after changing a query)
cd NibKit && swift run nib-fidelity --report [scheme]   # the import report (HL4) for a scheme file, or for Sublime's own (read-only)
cd NibKit && swift build -c release --product nib-fidelity && cd .. && NibKit/.build/release/nib-fidelity --bench   # highlighting times at 2.4 and 5 MB (§6.5)
```

A Mac new to the team has to be registered as a device once, or team-signed builds stop at "Device … isn't registered in your developer account". That changes the user's developer account, so it's their step:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild -project nib.xcodeproj -scheme nib -configuration Debug -derivedDataPath build/DerivedData -destination "platform=macOS" -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
```

Don't name a NibKit product `nib`: Xcode makes a scheme for each package product, and one called `nib` took `-scheme nib` from the app (builds that compiled nothing of the app, 2026-09-29; the tool's product is `nib-cli`). `scripts/build-nib.sh` (which the scenario scripts use) checks the app is newer than every Swift source after building; after a build by hand, check the same (`find nib NibKit/Sources -name '*.swift' -newer build/DerivedData/Build/Products/Debug/Rune.app/Contents/MacOS/Rune.debug.dylib`). Scenario logs are in `build/scenarios/`; Nib's own Sync Log is `~/Library/Application Support/nib/sync.jsonl`, and a scenario's Nib's is `~/Library/Application Support/nib-scenarios/sync.jsonl` (its folder and settings are its own, PRD §6.4). The suite and the two-Mac test start the test file over, so don't run them beside a Nib in daily use that has it open (since 2026-10-06 no Mac's has it as its scratch, unless chosen in Settings). Build checks that mustn't touch the Debug app the user may be running go to their own `-derivedDataPath` (`build/DerivedData-check`), unregistered from LaunchServices after (`lsregister -u`). Before each launch the suite waits, up to 2 minutes, for iCloud to finish uploading the test file (`scripts/wait-uploaded.swift`, with a line under the scenario's heading when it did): Nib doesn't pause a file mid-upload, so a launch then opens it unheld (§4.3).
